# GAMEBOY LAB v3.0.4

## Summary

v3.0.4 is a focused interface-consistency release. The previous dark-mode
pass had allowed component-specific hover rules to overlap, leaving selected
segments, status text, filters, and action buttons with competing colours and
shadows. This release replaces those late overrides with an explicit state
contract: white is selected, light grey is Options hover, and deeper graphite
is Emulation hover.

The release also finishes the save-state carousel introduced during the same
work cycle. Preview images now come from the framebuffer stored in the state,
rather than the hidden startup canvas, and each state retains its original DMG
or GBC model when displayed and restored.

## Player-facing changes

- Selected segmented controls and GB/GBC library filters are white in dark
  mode; hovering an unselected control no longer looks like a selection.
- Options uses a light-grey hover with dark labels. Emulation settings uses a
  deeper graphite hover across buttons, explanations, reset actions, and range
  thumbs—not only its segmented controls.
- Nested status text such as **ON**, **OFF**, **RAW**, and the DMG/GBC year
  remains legible on every hover surface.
- Slider thumbs no longer cast drop shadows. After dragging, hover remains
  dormant until the pointer leaves and returns, preventing a flash at the
  release position.
- Library filter strips no longer lift or gain coloured shadows. Add ROM now
  rises vertically on cyan, while Table/Detail View slides sideways on
  magenta, making the two actions visually distinct.
- Save-state slots show a real 160×144 preview and carry the console model that
  created the state.
- Cartridge switching covers the LCD immediately and keeps it covered until
  the replacement core presents its first safe frame, closing the remaining
  white-frame path between games.
- Tabletop view now has the same Search control as detail view, the keyboard
  motion toggle sits at the end of Controls, and the duplicate Core Controls
  heading has been removed from Emulation settings.
- Advanced summaries have been rewritten in plain language, with the longer
  explanation kept directly beneath each control.
- The README now opens with a three-image overview and explains the portable
  file, console presentation, LCD response, library, saves, and benchmark
  limits in player-facing language.

## Interaction-system cleanup

- Replaced the competing `--dark-hover-*`, `--dark-control-*`, and
  component-local dark-mode overrides with selected, Options-hover, and
  Emulation-hover tokens.
- Scoped drawer hover rules to `#options-drawer` and `.emulation-deck`, so a
  control cannot inherit the palette of another surface.
- Preserved white selection tiles while hovering an already selected segment.
- Separated WebKit and Gecko range-thumb selector lists. An unsupported vendor
  pseudo-element can no longer invalidate the other browser's rule.
- Added pointer lifecycle handling for range inputs without adding React state
  or rerenders to a drag.
- Added an explicit `tabletop-view-toggle` class so view-switch and ROM-add
  animations no longer depend on button position in the toolbar.

## Save-state preview correction

The previous preview path sampled the visible source canvas. During normal
gameplay that canvas is hidden behind the WebGL renderer and may still contain
a startup frame, producing a blank or stale thumbnail. Save now reads the exact
RGBA framebuffer included in the exported machine state and encodes it through
a temporary 160×144 canvas. The shader, display scale, and UI overlays are not
baked into the preview.

The state wrapper already carried the full emulator snapshot. v3.0.4 exposes
its saved model to the carousel and keeps the existing model-switch-on-load
path, so a GBC state cannot be presented or restored as a DMG state and vice
versa.
