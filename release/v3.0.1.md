# GAMEBOY LAB v3.0.1 — release audit, audio hand-off, and UI consistency

> **Engineering summary (2026-08-03).** This maintenance release closes an
> audio start-up race and hardens the conformance tooling so a score is only
> reported when ROM bytes, boot images, model/revision, timing budget and pass
> protocol all agree. The controlled 76-ROM run is **GAMEBOY LAB 60/76** versus
> **SameBoy 1.0.3 65/76**, with no timeouts, crashes or malformed results. That
> is an observed, reproducible reference result—not an accuracy ranking: the
> current SameSuite checkout is newer than the 2018 APU note that is sometimes
> paraphrased as “74/76”. The old 64/76 label and +26.13%/+12.64% benchmark
> headline is retired. A fresh equal three-way core-only smoke run uses 120
> warm-up frames, 600 measured frames, and nine rotated-order trials. Its
> median throughput is **792.70 FPS DMG / 665.75 FPS CGB** for LAB,
> **405.94 / 477.36 FPS** for SameBoy, and **3,628.48 / 3,996.78 FPS** for
> the available Gambatte-libretro binary. These are host-throughput figures,
> not a claim that gameplay should run faster than hardware.

v3.0.1 is a focused maintenance release. It fixes the browser audio start
path, makes the option drawers visually consistent, and documents a fair
three-way benchmark without changing the emulated clock, video timing,
cartridge mapper, or save format.

## Changes

- Conformance reports now require an explicit boot policy and record every ROM,
  BIOS, model, revision, process status, and protocol result. Unknown revision
  names and a reference runner that exits inconsistently are rejected instead
  of becoming an apparently valid score.
- Revision comparisons now reject compact, truncated, or missing CGB boot
  images (the controlled directory input must be exactly 0x900 bytes; an
  explicit single-image path is rejected at the same boundary), and the
  SameBoy adapter must prove both the requested revision it received and the
  revision it actually selected. These input-evidence fields are part of the
  version-8 report schema, so older reports cannot be compared accidentally.
- Both runners now enforce the same normalized DMG base-clock cycle budget;
  SameBoy's internal 8 MHz counter is converted at the adapter boundary. A
  separately recorded host wall-clock stop is classified as a timeout.
- The comparator validates totals, status counts, hashes, selected revisions,
  boot sizes, and normalized cycle evidence before comparing scores. Incomplete
  or hand-edited reports fail closed instead of comparing missing fields.
- Reports now include a ROM source snapshot in addition to the content hash.
  This is important for SameSuite, whose generated `.gb` files are ignored by
  git: the harness makes that provenance limitation visible and rejects dirty
  tracked ROMs or incomplete manifest coverage.
- The SameBoy marker adapter no longer reads the `$CFFE` result byte through
  the emulated public bus while the CPU is running. It inspects bank-0 WRAM
  directly, so the diagnostic callback cannot change open-bus decay or timing.
  The rebuilt adapter still reproduces the observed 65/76 reference result;
  the fix closes a measurement hazard rather than inflating the score.
- Reference reports also include a clean source-tree snapshot alongside the
  runner binary hash, preventing a modified SameBoy checkout from being
  presented as the tagged reference build.
- LAB reports also content-address the exact emulator core and embedded BIOS
  source files used for the run. A commit label without those file hashes is
  not eligible for comparison, even when the working tree is intentionally
  dirty during development.
- Revision-family ROMs now carry their full candidate list in each report
  (`cgb0B`, `cgb0BC`, and `cgbDE`), while the documented canonical representative
  remains explicit. This prevents a one-run family representative from being
  misread as proof for every silicon revision.
- A revision score now requires the directory-based BIOS mapping and an adapter
  proof of its actual model/revision. The paired comparator rejects differing
  ROM, BIOS, model, cycle, protocol, or exclusion inputs before showing a score.
- Performance comparisons now include generated PCM and terminal APU state in
  their output checksum. A speed result is labelled ineligible when the paired
  output changes, so an accuracy change cannot be presented as a free speedup.
- The closing tail of the GBC BIOS startup jingle now reaches the audio output
  instead of being removed by the host DC-blocking filter.
- Samples generated while `AudioContext` and the worklet are starting are
  queued for the short hand-off window, then delivered to the selected output
  backend in order.
- The pre-start queue is capped at two seconds and is cleared on an explicit
  audio reset, so a blocked autoplay context cannot replay stale audio after a
  cartridge change.
- Existing latency, buffering, frame-skip, and volume controls retain their
  previous behaviour.
- Options that use the green side indicator now share the application-data
  panel's centre-grown selection animation. The shared rule prevents one
  drawer from snapping while another scales from an edge. LCD, ghosting,
  contrast, and manual-scale controls now use the same 16px control rhythm.
- The consumer README was rewritten around playing, controls, saves, display
  choices, offline use, and troubleshooting; engineering methodology remains
  at the end rather than interrupting the first-run path.

## Verification

| Check | Result |
| --- | ---: |
| Repository tests | **99/99** |
| ESLint | pass |
| Mooneye acceptance (production profile) | **70/70**, 0 timeouts |
| SameSuite revision matrix (LAB, provisional) | **60/76**, 0 timeouts |
| Mealybug DMG-blob exact frames | **1/24** |
| Mealybug DMG-blob structural average | **96.0343%** |

The remaining SameSuite cases are revision-specific APU fixtures. They stay in
the report; no user-facing hardware-revision selector is used to make the
production result look better.

The prior +26.13%/+12.64% throughput headline is superseded. The corrected
three-way run used identical ROM hashes, model selection, post-boot policy,
warm-up, measured-frame count, and rotated backend order. LAB's p10-p90
throughput spread was 625.15-822.60 FPS for DMG and 577.73-741.97 FPS for
CGB. These numbers describe available core/PPU/APU headroom on the audit
machine, not faster-than-hardware gameplay; DOM, CSS, shaders, and host audio
were deliberately excluded.

## Reference smoke run

Tetris and Tetris DX were each run with the same post-boot baseline through the
production build, SameBoy 1.0.3, and the available Gambatte-libretro binary.
This is a throughput/frame-delivery smoke check, not a pixel-identity test:
the three cores intentionally retain their own colour encoders and framebuffer
formats. Every backend produced a stable per-run hash.

| Core | Tetris (DMG) | Tetris DX (CGB) |
| --- | --- | --- |
| GAMEBOY LAB (post-boot) | `cd0102ac` | `e885690b` |
| SameBoy 1.0.3 (post-boot) | `c6c0a5e4` | `e0b3e3c3` |
| Gambatte-libretro (bootloader disabled) | `45a34bd7` | `d5b35d4f` |

For context, the corrected independent SameBoy harness produced **65/76**
(CGB-0/A/B/C/E routing, exact boot mapping, and actual selected-revision
proof) on the same manifest. Eleven cases failed and none timed out, crashed,
or produced malformed protocol output. Six CGB-E failures do not match the
two exceptions described by the [SameSuite APU documentation](https://github.com/LIJI32/SameSuite/tree/master/apu),
so this remains an observed reference result rather than an accuracy ranking.
The previous 64/76 output did not retain enough per-case evidence to explain
its one-point difference; it is discarded rather than reverse-engineered into
a claim.
The Gambatte check was limited to the available libretro binary, so no
source-level conformance score is claimed for it.

The cited SameSuite APU README is a historical document last changed in 2018,
when its test set contained 60 ROMs. Its “all but two” statement is therefore
not a documented 74/76 result for the current 76-ROM checkout. The current
adapter records this discrepancy instead of converting it into a release
claim.

The complete JSON for the equal smoke run is checked in at
`release/benchmarks/v3.0.1-three-way.json`.

The next accuracy pass remains focused on the revision-sensitive CGB APU
cases. It will only be promoted when the complete matrix improves without a
regression in the production acceptance set.
