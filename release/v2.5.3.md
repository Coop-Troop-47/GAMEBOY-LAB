# GAMEBOY LAB v2.5.3 — smoother mid-line DMG colour changes

This is a focused follow-up release. It keeps the larger v3.0 accuracy work
behind the broader test gate instead of making a major-version claim early.

## What you should notice

DMG games that change their palette while a line is being drawn now hold the
old in-flight pixels for the measured hardware interval before applying the
new colours. In a game this makes raster wipes, status bars, scene transitions
and split-screen colour effects look less stepped and less likely to show a
wrong-width colour band. The change is DMG-only; native GBC rendering and the
fixed Game Boy clock are untouched.

## Measured improvement

The 24-case DMG picture suite moved from **94.1665% to 94.6823%** structural
frame agreement: **+0.5158 percentage points (+0.55% relative)**. The two
palette-change cases improved by about **6.2 percentage points each** (roughly
**6.8–7.0% relative**); the remaining cases stayed at their previous scores.

The project regression suite is **60/60**, and the 78-case SameSuite run still
completed with **55 passing cases and 0 timeouts**. Six representative games
kept their existing frame/CPU checksums, so this is a visual timing refinement,
not a faster or altered emulated machine.

v3.0.0 remains deliberately gated for the larger revision-aware PPU/APU work.
It will ship only when that broader work improves the overall accuracy results
while maintaining the emulator's measured browser headroom.
