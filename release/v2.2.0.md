# GAMEBOY LAB v2.2.0 — Window Fetch Accuracy and Reproducible Performance

v2.2.0 is a focused PPU accuracy release. It tightens the model of the LCD
fetch phase without changing the CPU/APU clock, and makes the performance
measurements used by the project resistant to long-process JIT and heap bias.

## What changes in games

- Window rendering now tracks the hardware's visible fetch phase instead of
  treating the window as a second whole-line renderer. Mid-scanline `WX`,
  `WY`, `LCDC` window-enable and window-map changes therefore take effect at
  the correct fetch boundary. Games that use status panels, masks, wipe
  transitions, or split-screen windows show fewer stale tiles and fewer
  one-pixel seams.
- The window line counter advances only when a window line was actually
  drawn. Lines skipped before `WY`, or lines where the window is disabled,
  no longer consume a row. This matters for games that animate a window in
  and out or reuse a window tile map for multiple panels.
- Background tile-map, tile-address-mode, and high `SCX` fetch latches are
  refreshed at source-tile boundaries. Mid-line scrolling and tile-map swaps
  no longer re-read the wrong half of a tile, improving scrolling layers and
  raster effects while preserving the fine-scroll discard from transfer start.
- Window and background state is included in save-state snapshots, so loading
  during an active transfer resumes the same pixel phase rather than producing
  a transient line mismatch.

## Measured accuracy

- Mealybug Tearoom DMG structural match: **86.6361% → 88.7153%**, a gain of
  **2.0792 percentage points** (**2.40% relative**). The exact-case count is
  intentionally still reported separately; structural similarity is not a
  claim of silicon equivalence.
- The strongest gains are window-register cases: `lcdc_win_en_change_multiple`
  rose from **65.8594% to 83.1944%**, and the corresponding `WX` case rose to
  **95.4036%**. Window-map, background-map, tile-select, and high-`SCX`
  cases also improved.
- Mooneye production-model acceptance remains **66/66 applicable tests** and
  emulator-only coverage remains **28/28**.
- Selected Blargg CPU, DMG/GBC sound, and memory-timing groups remain
  **41/41**. SameSuite APU remains **47/70**; the remaining cases are not
  silently counted as solved.

## Measured efficiency

The release benchmark uses five trials of 600 measured frames after 120 warm-up
frames, with every trial in a fresh `node --expose-gc` process. This prevents a
slow final cartridge, JIT tiering, accumulated heap, or thermal drift from
being presented as an emulator regression or improvement.

| Cartridge/model | v2.1.0 median | v2.2.0 median | Change |
| --- | ---: | ---: | ---: |
| Super Mario Land, DMG | 1,035.41 fps | 1,052.55 fps | **+1.66%** |
| Link's Awakening, DMG | 1,128.53 fps | 1,164.90 fps | **+3.22%** |
| Pokémon Blue, DMG | 1,418.51 fps | 1,481.26 fps | **+4.42%** |
| Wario Land 3, GBC | 703.56 fps | 717.61 fps | **+2.00%** |
| Shantae, GBC | 672.46 fps | 683.24 fps | **+1.60%** |
| Pokémon Crystal, GBC | 817.44 fps | 840.61 fps | **+2.83%** |

The practical result is more headroom for the browser's compositor, LCD shader,
audio worklet, library animation, and input handling while the emulated machine
still runs at its fixed ~59.7275 Hz cadence. It does not make the console run
faster; it reduces the chance that a busy frame misses its presentation deadline.

## Tooling and audit changes

- `scripts/core-benchmark.mjs` now isolates trials by default and records
  `isolatedTrials` in its JSON report. `--no-isolate` remains available for
  quick exploratory profiling.
- The benchmark checksum is unchanged for every paired cartridge, confirming
  that the throughput change is not a different execution path or skipped
  frame.
- The standalone build remains a single offline HTML file; no emulator core,
  ROM, BIOS, or deployment dependency is fetched at runtime.

## Known limits

This is not a claim that finite public suites prove “world's most accurate.”
The remaining high-value work is a full hardware FIFO/fetcher model across
DMG/CGB revisions, the outstanding SameSuite APU cases, OAM-corruption and
DMA-bus coverage, special cartridge peripherals (MBC6/MBC7/Camera/HuC), and
real browser-device input-to-photon/audio-latency measurements. Those are kept
as explicit follow-up work rather than hidden behind a headline percentage.
