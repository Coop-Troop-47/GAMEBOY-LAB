# GAMEBOY LAB v2.4.0 — more room for games, shaders and sound

v2.4.0 is a focused performance release between the larger accuracy milestones.
It keeps the emulated hardware timing and every tested game result unchanged,
while making the core spend less time looking up cartridge memory.

## What you should notice

When a game is scrolling, drawing lots of sprites, playing music, and using the
LCD shader at the same time, the browser has a little more breathing room. That
reduces the chance that a busy scene, audio delivery, or the surrounding UI has
to compete for the same short slice of CPU time. Gameplay still runs at the
real Game Boy cadence; this is extra headroom, not an artificial speed-up.

## Measured improvement

Five clean-process trials per game used 120 warm-up frames and 600 measured
frames. All six tested cartridges produced the same final framebuffer/CPU
checksums as v2.3.0:

| Game | Model | Available processing headroom |
| --- | --- | ---: |
| Super Mario Land | DMG | **+1.98%** |
| Link's Awakening | DMG | **+3.89%** |
| Pokémon Blue | DMG | **+3.20%** |
| Wario Land 3 | CGB | **+3.11%** |
| Shantae | CGB | **+1.94%** |
| Pokémon Crystal | CGB | **+3.90%** |

The median gain across the set is **+3.16%**.

## Verification

- **58/58** project tests pass.
- The DMG reference-image score remains **92.9402%**.
- SameSuite APU remains **47/70**, with no timeouts.
- Mapper, RTC, BIOS, save-state, cartridge, standalone-build, and checksum
  checks remain green.

The CGB envelope experiment was not included because it did not improve the
audio conformance score. v3.0.0 remains reserved for the broader PPU/APU
accuracy work once it can improve the external tests without giving back this
performance headroom.
